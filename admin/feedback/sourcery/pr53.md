### Bug #1: Test Helper Misuses fireEvent Parameter

**Severity**: 🔴 HIGH
**Type**: Bug (Runtime Error)
**Location**: `frontend/src/__tests__/test-utils/custom-render.tsx`

**Description**: 
The fireEventWithAct helper attempts to call its first parameter as a function (fireEvent(element, event)), but tests are passing the non-callable fireEvent object from @testing-library/react. This causes a runtime error. For click events, an unnecessary event object is also passed.

**Affected Locations**:
- `frontend/src/__tests__/test-utils/custom-render.tsx` (primary)
- `frontend/src/__tests__/pages/PokemonPage.test.tsx#L312-L313`
- `frontend/src/__tests__/pages/PokemonPage.test.tsx#L357-L358`

**Root Cause**:
The helper function signature expects `fireEvent` to be callable, but the actual usage pattern passes the fireEvent object and then tries to call it with element and event parameters.

**Impact**:
- Runtime errors when fireEventWithAct is used
- Tests may fail or behave unexpectedly
- Incorrect event handling pattern

**Recommended Fix**:
Remove the fireEventWithAct helper entirely since:
1. The current implementation is fundamentally flawed
2. Tests have been successfully migrated to use act() directly
3. The helper adds unnecessary complexity
4. Direct act() usage is clearer and more maintainable

**Priority**: 🔴 HIGH - Should be addressed in next session (Task 4)
